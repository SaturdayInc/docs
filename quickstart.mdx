# Quickstart

## 1. Get your API key

**Your own key:** a key comes with any paid Saturday plan, member or coach. Sign in at [saturday.fit/api](https://saturday.fit/api) and make it; it is shown once and emailed to you. It covers 10 athletes; to cover more, write to [api@saturday.fit](mailto:api@saturday.fit) about what you're building. Not sure which way in fits you? See [Getting Access](/access).

**Platform partners:** keys come with your agreement. Contact [api@saturday.fit](mailto:api@saturday.fit).

Keys carry an environment prefix. Production keys start with `sk_live_`, sandbox keys with `sk_test_`. Each environment keeps separate key records, so a key issued by the sandbox does not authenticate against production. See [Authentication](/authentication#environments) for what each environment does and which base URL it uses.

<Note>
  Treat your key like a password. It authenticates every request and spends your daily call allowance.
</Note>

The examples below use the production base URL and read your key from `SATURDAY_API_KEY`. For sandbox work, use an `sk_test_` key and the sandbox base URL, `https://test-api.saturday.fit`:

```bash
export SATURDAY_API_KEY="sk_live_..."
```

## 2. Create an athlete

Calculations are sized to an athlete. Store one with the answers Saturday needs for exact numbers: sex, year of birth, weight and the fueling profile.

```bash
curl -X POST https://api.saturday.fit/v1/athletes \
  -H "Authorization: Bearer $SATURDAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "user-42",
    "sex": "female",
    "year_of_birth": 1990,
    "weight_kg": 62,
    "settings": {
      "sweat_level": 5,
      "saltiness": 5,
      "satiety_level": 5,
      "fitness_level": 5,
      "carb_experience": "range_40_60",
      "usual_carb_consumption": "range_60_80",
      "concerns_answered": true
    }
  }'
```

The response is the stored athlete, with `"profile_complete": true` and an `id`:

```json
{
  "id": "b0bffebc-6575-4689-b97f-4a3bbf9cd364",
  "partner_id": "your-partner-id",
  "external_id": "user-42",
  "sex": "female",
  "year_of_birth": 1990,
  "weight_kg": 62,
  "settings": {
    "sweat_level": 5,
    "saltiness": 5,
    "satiety_level": 5,
    "fitness_level": 5,
    "carb_experience": "range_40_60",
    "usual_carb_consumption": "range_60_80",
    "concerns_answered": true
  },
  "created_at": 1797584400,
  "updated_at": 1797584400,
  "profile_complete": true
}
```

`external_id` is your own user ID, so you can find the athlete again with `GET /v1/athletes?external_id=user-42`. The [Onboarding](/guides/onboarding) guide covers collecting these answers from your users.

## 3. Calculate a session

Send the athlete's `id` with the session. `meal_before_min` (minutes since the athlete's last carb-rich meal) and `is_race` belong on every call: leave either out and the answer comes back as ranges.

```bash
curl -X POST https://api.saturday.fit/v1/nutrition/calculate \
  -H "Authorization: Bearer $SATURDAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "athlete_id": "b0bffebc-6575-4689-b97f-4a3bbf9cd364",
    "activity_type": "run",
    "duration_min": 90,
    "intensity_level": 5,
    "thermal_stress_level": 6,
    "meal_before_min": 120,
    "is_race": false
  }'
```

## 4. Read the response

```json
{
  "tier": "full",
  "carb_g_per_hr": 30,
  "sodium_mg_per_hr": 370,
  "fluid_ml_per_hr": 470,
  "total_carb_g": 45,
  "total_sodium_mg": 550,
  "total_fluid_ml": 700,
  "safety": {
    "max_safe_fluid_ml_per_hr": 1500,
    "max_safe_sodium_mg_per_hr": 3000,
    "confidence_score": 1,
    "requires_human_review": false,
    "warnings": [],
    "not_instructions": true
  },
  "attribution": {
    "text": "Powered by Saturday",
    "logo_url": "https://saturday.fit/logo.png",
    "link": "https://saturday.fit",
    "required": true
  },
  "precision": {
    "profile_complete": true
  },
  "tier_source": "trial",
  "trial_ends_at": 1797584569,
  "trial_calls_remaining_today": 14
}
```

| Field | What it means |
|-------|---------------|
| `carb_g_per_hr`, `sodium_mg_per_hr`, `fluid_ml_per_hr` | Per-hour targets, whole numbers, as the Saturday app shows them |
| `total_*` | Totals for the whole session |
| `precision.profile_complete` | When `precision` is present, `true`: these are exact numbers. `false`: the response carries ranges instead (step 5) |
| `tier`, `tier_source` | `full` with `trial`: the athlete's trial gives exact numbers for up to 14 days. It started with this call: 15 calls on the first day, then 5 a day, up to 42 in all |
| `safety` | Shown on every response. Show each warning to the athlete. `not_instructions` marks the numbers as guidance, not commands |
| `attribution` | Show it wherever you show the numbers |

To store the session and size the athlete's gels and drink mix against it, continue with [Activities](/guides/activities) and [Prep and Products](/guides/prep-and-products).

<Warning>
  Every response carries the full safety metadata, whatever the athlete's subscription: overdrinking can cause hyponatremia, which can be fatal.
</Warning>

## 5. Ranges and what they ask for

An athlete whose profile is missing answers gets ranges and a list of what to ask. The same session for an athlete stored without `carb_experience`:

```json
{
  "tier": "full",
  "carb_range_g_per_hr": "30-40",
  "sodium_range_mg_per_hr": "200-400",
  "fluid_range_ml_per_hr": "300-500",
  "safety": {
    "max_safe_fluid_ml_per_hr": 1500,
    "max_safe_sodium_mg_per_hr": 3000,
    "confidence_score": 0.69,
    "requires_human_review": false,
    "warnings": [],
    "not_instructions": true
  },
  "attribution": {
    "text": "Powered by Saturday",
    "logo_url": "https://saturday.fit/logo.png",
    "link": "https://saturday.fit",
    "required": true
  },
  "precision": {
    "profile_complete": false,
    "missing_fields": [
      {
        "field": "carb_experience",
        "required": true,
        "band_impact": { "carb_g_per_hr": 0, "sodium_mg_per_hr": 100, "fluid_ml_per_hr": 100 },
        "display_label": "how much carb your gut is trained for"
      }
    ],
    "missing_profile_fields": ["carb_experience"],
    "message": "For exact numbers, fill in what is missing. This athlete's profile is missing carb_experience: the onboarding link collects it.",
    "onboarding": {
      "message": "Answer the missing questions once, or have the athlete onboard in the Saturday app, to get exact numbers for this athlete."
    }
  },
  "tier_source": "trial",
  "trial_ends_at": 1797584572,
  "trial_calls_remaining_today": 14
}
```

`missing_fields` arrives most impactful first. `missing_profile_fields` names the athlete's answers to collect: ask those questions in your app, or, in the sandbox, send the athlete to `precision.onboarding.url` when the response carries one. A session input your request left out (`meal_before_min`, say) is listed in `missing_fields` too and in `missing_session_inputs`: it is yours to send. Check `precision.profile_complete` when the response carries `precision`, and the range fields when it does not, not `tier`, to tell exact numbers from ranges. `trial_ends_at`, like every time the API gives you, is in Unix seconds.

After the trial, an athlete without a Saturday subscription gets `"tier": "teaser"`: ranges and a `subscription_cta` with their subscribe link. See [Freemium Model](/guides/freemium-model) for how the tiers are decided.

## 6. Use an SDK

The TypeScript snippets in these guides use top-level `await`, so run them as ES modules: save them with an `.mts` extension, or set `"type": "module"` in your `package.json`.

<CodeGroup>

```bash TypeScript
npm install @saturdayinc/sdk
```

```bash Python
pip install saturday
```

</CodeGroup>

<CodeGroup>

```typescript TypeScript
import Saturday from "@saturdayinc/sdk";

const saturday = new Saturday({ apiKey: process.env.SATURDAY_API_KEY! });

const athlete = await saturday.athletes.create({
  external_id: "user-42",
  sex: "female",
  year_of_birth: 1990,
  weight_kg: 62,
  settings: {
    sweat_level: 5,
    saltiness: 5,
    satiety_level: 5,
    fitness_level: 5,
    carb_experience: "range_40_60",
    usual_carb_consumption: "range_60_80",
    concerns_answered: true,
  },
});

const plan = await saturday.nutrition.calculate({
  athlete_id: athlete.id,
  activity_type: "run",
  duration_min: 90,
  intensity_level: 5,
  thermal_stress_level: 6,
  meal_before_min: 120,
  is_race: false,
});

console.log(plan.carb_g_per_hr ?? plan.carb_range_g_per_hr);
```

```python Python
import os

from saturday import Saturday

with Saturday(api_key=os.environ["SATURDAY_API_KEY"]) as client:
    athlete = client.athletes.create(
        external_id="user-42",
        sex="female",
        year_of_birth=1990,
        weight_kg=62,
        settings={
            "sweat_level": 5,
            "saltiness": 5,
            "satiety_level": 5,
            "fitness_level": 5,
            "carb_experience": "range_40_60",
            "usual_carb_consumption": "range_60_80",
            "concerns_answered": True,
        },
    )

    plan = client.nutrition.calculate(
        athlete_id=athlete["id"],
        activity_type="run",
        duration_min=90,
        intensity_level=5,
        thermal_stress_level=6,
        meal_before_min=120,
        is_race=False,
    )

    print(plan.get("carb_g_per_hr", plan.get("carb_range_g_per_hr")))
```

</CodeGroup>

Both SDKs default to `https://api.saturday.fit` and take a base URL (`baseUrl` in TypeScript, `base_url` in Python) for the sandbox. They return the API's JSON as typed objects, raise typed errors, and retry short rate limits and server errors for you. Every method and its types: the [TypeScript SDK](https://github.com/SaturdayInc/saturday-node#readme) and [Python SDK](https://github.com/SaturdayInc/saturday-python#readme) READMEs.
